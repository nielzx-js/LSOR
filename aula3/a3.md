## 4. Procedimento

### 4.1. Identificação do sistema

```bash
hostname
cat /etc/os-release
```

Esses comandos identificam o nome da máquina e a distribuição Linux utilizada.

### 4.2. Identificação da interface de rede

```bash
ip addr
```

O comando permite identificar as interfaces de rede, os endereços IP, os prefixos de rede e os endereços MAC.

### 4.3. Identificação da rota padrão

```bash
ip route
```

O comando apresenta as rotas de rede e permite identificar o gateway padrão.

### 4.4. Teste de loopback

```bash
ping -c 4 127.0.0.1
```

Esse teste verifica a comunicação com a própria máquina.

### 4.5. Teste do gateway

```bash
ping -c 4 $(ip route | awk '/default/ {print $3; exit}')
```

Esse teste verifica a comunicação entre a máquina virtual e o gateway padrão.

### 4.6. Teste de conectividade externa

```bash
ping -c 4 8.8.8.8
```

Esse teste verifica a conectividade com um endereço IP externo.

### 4.7. Teste de resolução DNS

```bash
ping -c 4 google.com
```

Esse teste verifica se o nome de domínio é resolvido e se existe conectividade com o destino.

### 4.8. Teste entre o host e a máquina virtual

No PowerShell do Windows, executar:

```powershell
ping 10.0.2.15
```

Substituir `10.0.2.15` pelo endereço IP real da máquina virtual, caso seja diferente.

No modo NAT padrão, o host normalmente não consegue acessar diretamente o IP privado da VM pela rede física, pois a VirtualBox utiliza uma rede privada com tradução de endereços.

### 4.9. Configuração do modo Bridge

Na VirtualBox:

1. Desligar a máquina virtual.
2. Abrir **Configurações → Rede**.
3. Selecionar o adaptador utilizado.
4. Alterar o modo de conexão para **Placa em modo Bridge**.
5. Selecionar a interface de rede física do host.
6. Iniciar a máquina virtual.

Depois, executar novamente:

```bash
ip addr
ip route
```

Repetir os testes de conectividade e registrar os resultados obtidos no modo Bridge.

### Comparação entre NAT e Bridge

| Característica | NAT | Bridge |
|---|---|---|
| Endereço IP | Geralmente pertence à rede privada da VirtualBox | Geralmente pertence à rede local |
| Gateway | Gateway virtual da VirtualBox | Geralmente o gateway da rede local |
| Host acessa a VM | Normalmente não há acesso direto pelo IP privado | Geralmente possível, dependendo da rede e do firewall |
| Acesso à Internet | Geralmente disponível | Geralmente disponível, se a rede permitir |

Os resultados podem variar conforme a configuração da VirtualBox e da rede utilizada.

## 6. Problemas e soluções

Um problema que pode ocorrer é a impossibilidade de acessar diretamente o endereço IP da máquina virtual pelo host no modo NAT padrão.

Isso acontece porque a VM utiliza uma rede privada gerenciada pela VirtualBox. Uma possível solução é configurar o encaminhamento de portas ou utilizar o modo Bridge, desde que a rede permita a comunicação.

O problema efetivamente encontrado e a solução aplicada devem ser registrados com base nos testes realizados.

A prática permite compreender como os modos NAT e Bridge influenciam a conectividade de uma máquina virtual. Os comandos `ip addr` e `ip route` permitem identificar as interfaces, os endereços IP e o gateway padrão.

Os testes com `ping` ajudam a verificar a comunicação com a própria máquina, o gateway e destinos externos. A comparação entre os dois modos demonstra as diferenças de endereçamento e de acesso à rede.
